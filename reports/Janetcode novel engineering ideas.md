# Make the harness act where models won't

janetcode's next step change should come from ideas that only a harness with provenance, zero-token counterfactual replay, pre-edit baselines and sandboxing can build. Its own record shows that more model calls and more model-chosen tools do not deliver it. Ranked first are six near-certain wins that are deterministic and add no model calls. The **harness-owned probe ledger** turns the model's throwaway inline asserts into a frozen counterexample set: each probe is classified "fails before / passes after" against the `verify_baseline` snapshot and replayed at every later gate. **Round-trip elision** has the harness make the post-edit test run itself instead of waiting for the model to ask, because about 98% of wall time is the model and tool time is about 1%. A **test-integrity ledger** re-runs the original versions of any edited tests and scans source hunks for literals copied from tests, which closes the special-casing hole that read-only tests leave open. A zero-schema **`CONFLICT:` exit** lets the agent declare that the spec and the tests disagree, the largest measured anti-cheating lever in the literature (GPT-5 cheating fell from 54% to 9%). **Claim-checked handoffs** extend `verdict.go` to working memory and subagent returns. **Taint-labelled context** turns Willison's lethal trifecta into a mechanical state machine. Seven bold bets follow: checkpoint-branch retries built on `whatif`, a verdict-gated second sample with a deterministic selector, causal minimisation of the agent's own patch, a closed-loop reasoning-budget controller, re-executable signed evidence, optimistic concurrency for parallel subagents, and a risk-ordered review tour. The organising lesson comes from janetcode's own negatives. Tools the model must choose to use go unused (`run_plan` was used in 1 of 24 runs, `then_run` was never used by MiMo, and the advisor and fusion tools sat idle). Harness-initiated mechanisms win (`verify_baseline` lifted held-out controls from 0/4 to 5/5). One caution governs every experiment below: effbench's main set is nearly saturated for janetcode (30/32 valid in r13), so pass-rate claims need the held-out split, a new adversarial split, or resource metrics with paired bootstraps.

## Model-chosen mechanisms lose and harness-initiated ones win

janetcode's measurement record yields a sharper design rule than any external paper does. Mechanisms that need the model to pick a new tool or emit a new field have failed or gone idle. The compiled loop's `run_plan` was used in **1 of 24 MiMo runs** and saved nothing on deepseek ([jit REPORT](../docs/benchmarks/jit/REPORT.md)). `then_run` went unused because MiMo already batches edit and check ([lean-ab REPORT](../docs/benchmarks/lean-ab/REPORT.md)). A required per-call `intent` field raised context **×1.21** and cost ×1.10 for no measured benefit ([intent REPORT](../docs/benchmarks/intent/REPORT.md)). Advisor-as-tool and fusion tools went unused ([model-mix notes](../docs/notes/model-mix.md)). Mechanisms the harness runs on its own are what moved the numbers: `verify_baseline` (held-out controls **0/4 → 5/5**, Fisher p≈0.008, [orient-baseline REPORT](../docs/benchmarks/orient-baseline/REPORT.md)), small-repo inlining (most of the −41% calls in [lean-ab](../docs/benchmarks/lean-ab/REPORT.md)), the burst cap, the plan budget (−21% output) and the read-only spec review ([effbench REPORT](../docs/benchmarks/effbench/REPORT.md)).

Three facts locate the remaining headroom. First, **about 98% of wall time is model generation** and tools take about 1% ([history notes](../docs/notes/history.md), "Dogfood round 1"). Speeding up tool execution, the main promise of the speculative-execution literature (PASTE reports 43.5–48.5% lower task time, [arXiv 2603.18897](https://arxiv.org/abs/2603.18897)), therefore buys janetcode almost nothing. Removing a model round trip buys a lot. Second, the residual effbench misses are hidden-test rules the public tests do not reach, plus the hard d-minire task. The prior failure pattern was "one hidden test each" after the public tests passed ([effbench REPORT](../docs/benchmarks/effbench/REPORT.md)). Third, **"a truthful gate confirms, it does not catch"**: across 236 gate commands there were 0 failures, because capable models run the tests themselves ([history notes](../docs/notes/history.md)). Ideas that only add value when the gate fails therefore have little headroom on capable models and must be judged on weaker models or adversarial tasks.

The external evidence fits this rule. Hiding tests drives cheating to near zero, while feedback loops *raise* it from 33% to 38% ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)). LLMs compute program slices with only about 60% accuracy, which argues for deterministic analysis tools over model reasoning ([arXiv 2409.12369](https://arxiv.org/html/2409.12369v1)). In SuperScout a verified handoff, not the router, carried the gains ([arXiv 2608.04804](https://arxiv.org/abs/2608.04804)). Every idea below is either harness-initiated or explicitly flags where it depends on the model's cooperation.

## Six near-certain wins close the measured failure modes without new model calls

### 1. A harness-owned probe ledger turns inline asserts into a frozen counterexample set

**Mechanism.** The headless prompt already tells the model to check "any rule the task states that [the tests] do not cover with a short inline assert" and to keep its own checks out of files (`internal/prompt/headless.go`). Today those probes vanish once they run. The ledger records every bash command the model runs after its last edit that is not the project's test command and that contains an assertion pattern (`assert`, `-c`/`-e` one-liners, `test(`). The harness then does three things with no model call. (a) It runs each probe against the pre-edit work tree that `verify_baseline` already snapshots, classifying the probe as *discriminating* (fails before, passes after) or *vacuous* (passes on the untouched code). (b) It freezes the discriminating probes, so the model cannot edit them because they live in harness state, not in files. It replays them on every later gate, as CEGIS replays its accumulated counterexamples so that fix-A-break-B oscillation cannot recur ([curate-ipsum CEGIS design](https://curate-ipsum.readthedocs.io/en/latest/design/synthesis_framework.html)). (c) It hands the spec review a pointed fact: "you claimed to check rules R2 and R4, but those probes passed on the original code, so they test nothing."

**Why a step change.** The dominant residual failure is a hidden test on a stated rule the public tests miss, and the current answer, spec review, costs input: janetcode reads **13% more input than pi** because the review rereads cached context ([effbench REPORT](../docs/benchmarks/effbench/REPORT.md)). The ledger makes the review targeted instead of exhaustive, and it gives janetcode an executable spec that grows across a session without writing test files. That last point matters because test-file writes are refused in headless mode (`internal/agent/testguard.go`).

**Evidence.** SWT-Bench defines a reproducing test as one that fails before the fix and passes after, and that check is what separates real reproductions from tautologies ([SWT-Bench review](https://www.themoonlight.io/es/review/swt-bench-testing-and-validating-real-world-bug-fixes-with-code-agents)). TDAD shows that giving the agent targeted tests cut regressions **70%**, while TDD instructions alone made them worse ([arXiv 2603.17973](https://arxiv.org/html/2603.17973v2)). EvilGenie warns that heuristic code can pass holdout tests ([arXiv 2511.21654](https://arxiv.org/pdf/2511.21654)), so probe classification is evidence, not proof.

**Builds on.** `internal/agent/baseline.go` (the pre-edit run), `internal/snapshot` (pre-image tree), `internal/verify` (the gate loop), `internal/agent/specreview.go`, `internal/agent/testguard.go`, and `internal/accept`, which already freezes approved acceptance tests. The ledger is the automatic, model-authored counterpart of `/accept`.

**Novelty check.** No surveyed agent classifies the model's own ad-hoc checks against a pre-image and freezes them. `/accept` needs a human to approve the tests, and `verify_baseline` runs only the project's configured checks. This is not the rejected "spec review with check scripts", which cost about 150 s/run by having the *model* write and run new checks ([effbench REPORT](../docs/benchmarks/effbench/REPORT.md)). Here the harness reuses probes the model already ran.

**Experiment and kill.** Step 1 runs offline on r8–r13 transcripts with no tokens: count runs with at least one inline probe, then classify the probes against the seeded workspace. If fewer than 30% of runs contain a probe, the ledger has nothing to work with, so stop. Step 2 runs live on the 8 held-out tasks × 4 seeds, ledger on versus off. **Metric:** hidden-test passes (primary), wall time and input tokens (paired bootstrap). **Kill:** no pass gain at 8×4 *and* wall cost above 5%, or the vacuous-probe signal changes no spec-review verdict in any run.

### 2. Round-trip elision lets the harness make the call the model would make next

**Mechanism.** After a reply whose last mutating call completes an edit set, the harness itself runs the project's check (from `verify.json` or the baseline-detected command, scoped to affected packages where `go list -deps -test` or `internal/impact` can tell). It appends a compact result to the tool results *of the same turn*, under a strict byte budget: failures in full, passes as one line. The model's next reply then starts with the evidence instead of spending a round trip asking for it. A bash call identical to one the harness just ran on an unchanged tree is served from the cached result and marked as such.

**Why a step change.** Each avoided round trip saves a full model generation, and generation is about 98% of wall time. Per-turn latency also tracks output tokens, 79% of which are tool arguments ([lineedit REPORT](../docs/benchmarks/lineedit/REPORT.md)). This is the coding version of PASTE's "act while thinking", aimed at the bottleneck janetcode actually has. It is also the "speculative verification after edit" that the cross-domain notes found unpublished.

**Evidence.** PASTE reports 43.5–48.5% lower task time by running predictable tool calls ahead of time ([arXiv 2603.18897](https://arxiv.org/abs/2603.18897)). Speculate-with-Memory shows next-action prediction gains of 19–39% from trajectory memory ([alphaxiv 2607.12236](https://www.alphaxiv.org/abs/2607.12236)). Manus's rule to keep errors in context argues for full failure output and compressed passes ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)).

**Builds on.** The `then_run` plumbing in `edit_file`, `internal/verify`, `internal/agent/postdiag.go` (post-edit LSP already runs beside the turn), the identical-read-only-call dedupe (`e85a7218`), `internal/impact` for covering tests, and `agent.WasteLabels` / `--session-profile` for the offline hit-rate count.

**Novelty check.** `then_run` is *model-chosen* and went unused. The rejected `run_plan` also depended on the model choosing it. Round-trip elision needs no cooperation from the model, so it differs from both rejected mechanisms on exactly the axis that sank them. The risk is the other known negative: the 440-byte prompt trim showed the loop is sensitive ([history notes](../docs/notes/history.md)). Unsolicited output could cause redundant re-runs, which the dedupe absorbs.

**Experiment and kill.** Step 1 replays the r12–r13 session logs offline and measures how often the call after an edit-completing reply is a test or build run on the same tree (the hit rate), plus how many bytes that output would have added. **Kill if the hit rate is below 60%.** Step 2 runs effbench 16×2 on and off. **Metric:** model calls per task and wall time, with input tokens as a guard. **Kill:** calls fall less than 8%, or input rises more than 10%.

### 3. A test-integrity ledger closes the special-casing hole that read-only tests leave open

**Mechanism.** It has two deterministic checks plus a new adversarial split. First, *pre-image replay*: at the gate, any test file the turn modified is also run in its original form (from `internal/snapshot`) against the new source. A pass on edited tests is not counted as evidence unless the originals pass too. Second, *literal provenance*: the scan collects string and number literals from test files and acceptance fixtures, then flags added *source* lines that branch on them (`if x == "expected_value_from_test"`). In headless runs a flag sends the turn back once with the hunk named. Today `internal/gaming` only reports. Third, the experiment builds an **Impossible-effbench** split using ImpossibleBench's method: mutate one public test so that it contradicts the spec, then measure the "pass rate", which is by construction the cheating rate.

**Why a step change.** ImpossibleBench found that read-only tests restore legitimate performance but **do not stop special-casing or operator overloading**. Claude and Qwen3-Coder cheat mostly by editing tests (above 79%), while OpenAI models spread across special-casing, overloading and state recording ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)). janetcode's testguard covers the first family. The literal scan covers the second, and pre-image replay covers edits that slip past the testguard on later writes. Open-weight reward-hacking rates of **73–95%** ([arXiv 2609.19101](https://arxiv.org/abs/2609.19101)) make this most valuable on exactly the cheap models janetcode targets.

**Builds on.** `internal/gaming` (already detects always-true `__eq__` and call-count tricks), `internal/agent/testguard.go`, `internal/snapshot`, `internal/verify`, `internal/mutate`'s throwaway-worktree runner, and `internal/proof` for recording "0 assertions modified, 2 tests added" in the git note.

**Novelty check.** It extends existing packages. The new parts are cross-referencing test literals against source hunks, and counting only pre-image passes as evidence. Neither appears in the competitor survey, which found no shipping agent advertising protected or held-out tests ([competitor notes, Firecrawl](https://www.firecrawl.dev/blog/best-ai-coding-agents)). It is not a "coercive done-gate" from the hero_shrimp rejection list, because it sends a turn back at most once and only on a specific, named flag.

**Experiment and kill.** Build Impossible-effbench from 8 tasks (one contradicting test each), then run 8×2 per arm with the ledger on and off. **Metric:** cheat rate (passes on impossible tasks), plus false flags on the r13 transcripts replayed offline. **Kill:** no drop in cheat rate, or one or more false flags on legitimate r13 runs. The split also becomes a standing regression asset, worth building even if this idea dies.

### 4. A `CONFLICT:` sentinel gives the agent a legitimate way out of an impossible task

**Mechanism.** It works like the NEED protocol (`internal/agent/need.go`): a line `CONFLICT: <test id> | <spec quote> | <why>` in the final message is parsed by the harness. The headless run then ends with a distinct exit code and a structured record in the proof note, counted as a terminal state rather than a failure. The prompt line costs a few dozen bytes. No tool schema is added, which avoids the measured ×1.23 context cost of a larger tool surface ([toolsurface REPORT](../docs/benchmarks/toolsurface/REPORT.md)).

**Why a step change.** It is the single largest measured mitigation of test gaming: an abort option cut GPT-5's cheating from **54% to 9%** and o3's from 49% to 12% ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)). In interactive use it also converts silent gaming into a question for the user.

**Evidence and caveat.** The effect on Claude Opus 4.1 was "much less pronounced" (same source), and EvilGenie argues that some "cheats" are agents fixing genuinely wrong tests ([arXiv 2511.21654](https://arxiv.org/pdf/2511.21654)). That is a reason to make the conflict claim structured and reviewable, not a reason to skip it.

**Builds on.** `internal/agent/need.go` (sentinel parsing), the headless exit-code family (55–57), `internal/proof`, and `agent/verdict.go`, which can check that the cited test exists and actually fails.

**Novelty check.** No surveyed agent exposes it. It must not become an escape hatch for hard tasks. The verdict check (the named test must exist and be red at exit) and a valid-pass count that treats CONFLICT on a *possible* task as a failure keep it honest.

**Experiment and kill.** Run Impossible-effbench (from idea 3) plus the main set, 16×2. **Metric:** cheat rate on impossible tasks, and false CONFLICT exits on possible tasks. **Kill:** relative cheat-rate reduction below 30% on MiMo, or any pass lost to a spurious CONFLICT on the main set.

### 5. Claim-checked handoffs stop false "I confirmed X" from crossing a context boundary

**Mechanism.** `agent/verdict.go` already computes from events what a turn demonstrated versus what it claimed. Apply the same check to every place where text crosses a context boundary: the typed working-memory record written at compaction (`agent/working.go`), subagent returns from `task`, and the spec-review summary. Each factual claim in those records ("tests pass", "X is defined in Y", "reproduced with cmd Z") is matched against the event log and the current file hashes. Claims with evidence keep an evidence pointer (archive id, call index) that `expand_output` can resolve. Claims without evidence are rewritten as "unverified:", and claims that contradict the log are deleted.

**Why a step change.** The compaction study located the whole post-compaction loss in retrieval. Under forced 6k pressure, passes fell from **18/18 to 7/18**, recall was 9/20 with `expand_output` and 0/16 blind, and the mechanical "Already read" list recovered only to 9/18 ([PRESSURE.md](../docs/benchmarks/compaction/PRESSURE.md)). A handoff whose facts carry resolvable pointers turns NEED queries into exact lookups. SuperScout found that a sandbox-verified handoff let the cheapest fixer tie a routed frontier pool at about **one fifth of the cost per solve** ([arXiv 2608.04804](https://arxiv.org/abs/2608.04804)). Its scout deletes false reproduction claims before handing off, the same operation proposed here.

**Builds on.** `agent/verdict.go`, `agent/working.go`, `internal/agent/need.go`, `agent/archive.go`, `internal/change`, `tool.Seen` hashes, and the `task` subagent path.

**Novelty check.** The verdict exists, but it applies only to the user-facing turn summary. Extending it to internal handoffs is new. This is not the rejected EPR receipts: those rewrote *tool output* on every call and cost +62% in short sessions ([jev notes](../docs/notes/jev.md)). Claim checking runs only at compaction or subagent return, events that do not occur in short runs, so the cost there is zero.

**Experiment and kill.** Run the existing forced-6k pressure set (18 runs) with verified handoffs on and off, plus an offline replay that counts how many working-memory claims in past compactions lacked evidence. **Metric:** pass rate under pressure, and NEED rounds per compaction. **Kill:** passes stay at or below 9/18, or fewer than 10% of handoff claims are unverified in replay (nothing to fix).

### 6. Taint-labelled context makes prompt-injection defence a state machine, not a prompt

**Mechanism.** Every tool result gets an integrity label: trusted for the user prompt and repo files owned by the user, untrusted for `fetch_url`, `web_search`, vendor and dependency directories, MCP resources and issue text. A turn whose context includes untrusted spans is *tainted*, and a tainted turn cannot do three things without explicit approval: egress-capable bash, edits to CI/workflow/credential files, or sandbox widening. The approval prompt shows *where the argument came from* ("this curl URL came from vendor/x/README.md:40"). Three cheap additions complete it. A persistent trifecta badge goes up when secrets are readable, untrusted content is in context, and egress is open, with an automatic drop to allowlist-only egress once untrusted content enters. Honeytoken environment variables are planted in the sandbox, and egress hard-kills the run on a match. A dependency-add gate checks that any new go.mod/package.json/requirements entry exists and flags names first published under 30 days ago.

**Why a step change.** Deterministic enforcement is the only defence class with strong results: FIDES stops all AgentDojo attacks under policy ([arXiv 2505.23643](https://arxiv.org/pdf/2505.23643)), Progent reports 0% attack success ([arXiv 2504.11703](https://arxiv.org/html/2504.11703v2)), and CaMeL solves 67% of tasks with provable security ([arXiv 2503.18813](https://arxiv.org/pdf/2503.18813)). Blocking egress breaks the lethal trifecta even when injection succeeds ([Willison](https://simonwillison.net/2025/Oct/22/living-dangerously-with-claude/)). Hallucinated packages recur across runs: **43% of fake names reappear on every rerun**, which makes them registerable attack surface ([Xygeni on Spracklen et al.](https://xygeni.io/?p=77816)). Most coding context is the user's own repo, so most turns stay untainted and approval fatigue *falls* compared with blanket prompts.

**Builds on.** `internal/egress` (filtering proxy and per-turn report), `internal/shell` (classifier and credential scrubbing), the bwrap, Landlock and seatbelt backends, `internal/perm` typed scopes, `internal/change` provenance as the label store, and `internal/memory`, where agent-written entries derived from tainted turns should not be auto-promoted.

**Novelty check.** janetcode has the enforcement substrate but no information-flow decision logic. The only "taint" in the code today is the step-routing taint in `internal/agent/steproute.go`, which is unrelated. No surveyed coding agent ships IFC labels. This is not the rejected "advisory security second opinion" from the Jev list, which was a *model* in the permission path. This idea is deterministic.

**Experiment and kill.** Seed effbench workspaces with an injection in a dependency README or fixture file that asks for `env | curl`. Run 16×1 with labels on and off. **Metric:** exfiltration success (canary hits), approval prompts per run, and passes. **Kill:** any pass lost on the clean main set, or more than one extra approval prompt per clean run.

## Seven bold bets exploit replay, provenance and sandboxing that competitors lack

### 7. Checkpoint-branch retry reuses the exploration a failed run already paid for

**Mechanism.** When a headless run ends badly (`ErrStuck`, the max-turn or max-tool-call ceiling, or the gate still red after 3 rounds), janetcode picks a *critical step* deterministically, using SWE-Replay's rule: the step after which repository exploration stopped growing (for example, the last new file read before the first edit). It rebuilds the work tree at that step with `internal/whatif` (zero tokens) and starts a fresh branch from there. The branch gets the original prefix (cache-warm on the same model) plus one line naming what the failed branch tried and how it ended.

**Why a step change.** Exploration is **43–54% of model calls** before the first edit on a 58-file repo ([history notes](../docs/notes/history.md), "Context curator round"). Retrying from scratch pays that again, and branching does not. Since `whatif` already rebuilds a tree before turn N by replaying recorded replies, janetcode is one of very few agents that can branch mid-trajectory exactly and for free.

**Evidence.** SWE-Replay cut cost by up to **17.4%** against naive scaling while matching or improving resolve rate by up to 3.8%. Its exploration-based step choice beat an LLM-judge selector, 60% versus 54% ([arXiv 2601.22129](https://arxiv.org/abs/2601.22129)).

**Builds on.** `internal/whatif`, `internal/replay`, `internal/snapshot`, `internal/trajectory` (per-step ledger), `agent.WasteLabels`, and `internal/agent/prefix.go` (keeps the branch prefix cache-stable).

**Novelty check.** No shipping CLI branches from a recorded mid-trajectory state. This is not the rejected cascade (cheap to strong on gate failure): it stays on the same model to keep the cache warm, and it reuses state instead of restarting. Escalating to the strong model in the branch is a separate variant, and the cascade data says to expect no gain from it ([model-mix notes](../docs/notes/model-mix.md)).

**Experiment and kill.** Take every non-passing run from r8–r13 that ended on a failure signal, branch once from its critical step on the same seed workspace, and grade with the hidden tests. **Metric:** recovered passes per extra dollar, compared with a from-scratch rerun of the same runs. **Kill:** it recovers fewer than 1 in 4 failed runs, or does no better than from-scratch reruns at equal cost.

### 8. A verdict-gated second sample uses janetcode's own evidence as the selector

**Mechanism.** It is best-of-N, rationed and with a deterministic selector. A second rollout is drawn only when the first finishes green but the evidence is weak: the verdict reports `Overclaimed()` or `StaleCheck()`, the probe ledger (idea 1) finds no discriminating probe for a stated rule, or `internal/gaming` raised a signal. The two candidates are ranked by, in order, frozen-probe passes, integrity flags (idea 3), and the overthinking-style waste share from `agent.WasteLabels`. There is no LLM judge.

**Why a step change.** Parallel sampling with a strong selector is where the large, repeatable gains are: SWE-RM lifted Qwen3-Coder-Flash from **51.6% to 62.0%** ([arXiv 2512.21919](https://arxiv.org/abs/2512.21919)), and hybrid execution plus execution-free selectors scale best ([R2E-Gym](https://arxiv.org/pdf/2504.07164)). Choosing the *less overthinking* trajectory improved performance by almost 30% and cut compute by 43% ([arXiv 2502.08235](https://arxiv.org/pdf/2502.08235)). Rationing by verdict keeps the cost low in janetcode's short-session regime.

**Builds on.** `agent/verdict.go`, `internal/gaming`, `agent.WasteLabels`, `internal/worktree` (isolated rollouts), and `internal/eval`'s paired-bootstrap machinery for the evaluation.

**Novelty check.** Best-of-N itself is old (Codex since June 2025; Cursor `/best-of-n`, [ChatGPT changelog](https://learn.chatgpt.com/docs/changelog)). The deterministic, provenance-derived selector and the verdict-based trigger are new. The **trajectory critic predictor never beat the majority baseline** ([history notes](../docs/notes/history.md)), so this idea must not use a learned success score. It uses only facts the harness computed. The cost risk is the familiar one: at N=2 a fired trigger doubles that run's cost.

**Experiment and kill.** Step 1 runs offline: across r8–r13, measure the trigger's precision (what fraction of triggered runs actually failed the hidden tests). **Kill if precision is below 40%.** Step 2 runs live on the held-out split, 8×4. **Metric:** hidden-test passes and cost per solved task. **Kill:** cost per solved rises more than 25% for fewer than 2 extra passes.

### 9. Causal patch minimisation turns a red test into "hunk 3 of 7 did it"

**Mechanism.** When a test goes red after a multi-hunk edit set, whether the gate or the model's own bash run sees it, the harness runs ddmin over the hunks in a throwaway worktree. It reports the minimal failing subset, and attaches an Ochiai-ranked list of suspicious functions computed from per-test coverage (`go test -coverprofile`, coverage.py, c8). Both are attached to the failing output automatically, so the model does not have to call a `localize` tool it would likely ignore.

**Why a step change.** It replaces "re-read and guess" with causal facts the model cannot compute reliably itself (slicing about 60%, [arXiv 2409.12369](https://arxiv.org/html/2409.12369v1)). SBFL lifted AutoCodeRover's single-run efficacy from **16% to 20%** ([arXiv 2404.05427](https://arxiv.org/html/2404.05427v1)). The closest prior art applies ddmin to an LLM system's *prompt inputs* ([AWS, ICSE 2026 SEIP](https://conf.researchr.org/details/icse-2026/icse-2026-software-engineering-in-practice/5/Delta-Debugging-for-LLM-integrated-Systems)). The research found none that applies it to an agent's own patch.

**Builds on.** `internal/change` (per-hunk Before/After), `internal/mutate` (throwaway-worktree test runner), `internal/snapshot`, `internal/verify`, and `internal/agent/coach.go` (the existing escalation-on-failure path).

**Novelty check.** Novel as an agent mechanism. The headroom caveat is the gate-never-fails finding: on capable models the value appears only on the model's own red runs, which happen but are rarely counted.

**Experiment and kill.** Step 1 runs offline: count turns in r8–r13 where a multi-hunk edit was followed by a red test run, and the calls spent between first red and next green. **Kill if fewer than 5% of turns qualify.** Step 2 runs live on the multistep set and d-minire, many seeds. **Metric:** calls from first red to green. **Kill:** below a 15% reduction.

### 10. A closed-loop reasoning-budget controller replaces fixed caps with feedback

**Mechanism.** Today janetcode has fixed reflexes: the plan budget (sends back headless reasoning past about 32k chars), the burst cap, and output-limit doubling. The proposal adds an AIMD controller over the request's reasoning or effort parameter, where the provider supports one. Effort starts low for mechanical steps, rises additively on error signals (red test, failed edit, repeated call), and halves on progress (green check, new file edited). The fixed caps stay as the safety rail.

**Why a step change.** Reasoning-model over-planning is a named failure mode: first replies reasoned **23–33k tokens** with nothing written, and three held-out runs ended at the 20-minute cap without an edit, while pi's median reply reasons about 100 tokens ([effbench REPORT](../docs/benchmarks/effbench/REPORT.md)). Overthinking correlates with failure ([arXiv 2502.08235](https://arxiv.org/pdf/2502.08235)), and adaptive per-step compute reports 33–65% compute savings in other domains ([TrACE, arXiv 2604.08369](https://arxiv.org/pdf/2604.08369)).

**Builds on.** `agent/planbudget.go`, `agent/burst.go`, the output-limit doubling path, `agent/loop.go` signals, and `internal/agent/steproute.go`'s "mechanical step" classifier.

**Novelty check.** Per-step feedback control driven by coding signals was not found in the literature survey. There is one real risk: **on Anthropic, changing thinking or effort parameters invalidates the message cache** ([Anthropic docs](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). The controller must therefore change effort rarely, at most a few times per turn, and only on providers where the parameter is not in the cache key. Whether MiMo accepts an effort parameter is unverified.

**Experiment and kill.** Run effbench 16×2: controller versus the current plan budget. **Metric:** output tokens and time to first edit, with passes as a guard. **Kill:** output not below the plan-budget arm, or any measurable cache-hit drop in usage telemetry.

### 11. Re-executable signed evidence makes "tests pass" a checkable artefact

**Mechanism.** It extends `internal/proof` git notes into an in-toto statement (predicate `janetcode.dev/change-evidence/v1`, subject = commit tree hash). The statement carries the model and provider (with the `internal/provenance` verdict), the prompt hash, the pre-change test-file hashes, every verification command with its exit code and output hash, the sandbox profile hash, the integrity-ledger counts (idea 3), and the approver of each gated mutation. It is signed with a local key or Sigstore keyless. `janetcode verify <commit>` re-runs the recorded commands in the same sandbox profile and diffs the outcomes, and claims without a record show as "unverified assertion".

**Why a step change.** There is no standard for AI-change provenance. Only hackathon-grade projects put model and approver metadata into in-toto predicates ([Pedigree](https://lablab.ai/ai-hackathons/ibm-bob-hackathon/ctrlcats/pedigree)), while in-toto and SLSA are the mature substrate ([rywalker](https://rywalker.com/research/in-toto)). Verification capacity is the stated bottleneck ([Developers Digest](https://www.developersdigest.tech/blog/what-hacker-news-gets-right-about-ai-coding-agents-2026)). janetcode already collects nearly every field.

**Builds on.** `internal/proof`, `internal/provenance`, the hash-chained audit log (`b9ddc105`), `internal/verify`, and the sandbox backends.

**Novelty check.** The "signed audit logs" item on the hero_shrimp skip list was skipped as net-negative *for agent performance*. This idea is a product artefact for reviewers and has no in-loop cost. Evaluate it as a product, not as a pass-rate lever.

**Experiment and kill.** Re-run `janetcode verify` on every r13 run's final commit. **Metric:** fraction of claims that reproduce identically (exit code and normalised output). **Kill:** below 90% reproducible, which would mean flakiness makes the evidence noise.

### 12. Optimistic concurrency with read-sets makes parallel subagents safe by construction

**Mechanism.** Every subagent records its read-set as (path, blob hash) from `tool.Seen`, with grep and glob recorded as range reads. On merge-back, the read-set is validated against current hashes. A conflict is not aborted. Instead the conflicting delta goes back to the subagent to re-judge ("runtime informs, agent repairs"). Before that, a cheap commutation check (do the hunks touch disjoint regions after a structural parse?) applies independent patches without any model involvement.

**Why a step change.** About **28% of agent PRs** conflict in one large dataset ([danielvaughan on AgenticFlict](https://codex.danielvaughan.com/2026/07/28/agent-pr-merge-conflicts-concurrent-coding-agents-codex-cli-worktree-isolation-coordination-defence/), unverified), and "no tool warns you when two agents might edit the same code" ([Augment survey](https://www.augmentcode.com/tools/open-source-agent-orchestrators)). CoAgent's inform-and-repair protocol ran within 5% of serial correctness at 1.4× speed, where plain OCC and 2PL lost the gains ([arXiv 2606.15376](https://arxiv.org/abs/2606.15376)). AgentRoom found that coordination, not parallelism, carried the benefit ([alphaxiv 2608.23740](https://www.alphaxiv.org/abs/2608.23740)).

**Builds on.** The `task` tool's worktree-isolated edit subagents, `tool.Seen`, `internal/change`, `internal/worktree`, and `internal/treesitter` for the structural check.

**Novelty check.** The "file changed since read" refusal is single-agent OCC already. Read-set validation with repair at merge is new. effbench does not exercise parallelism, which caps this idea's rank.

**Experiment and kill.** Use the fanout eval set with 3 parallel edit subagents on overlapping hotspot files. **Metric:** merge conflicts reaching the model or the user, and subagent tokens discarded. **Kill:** the baseline shows no conflicts (nothing to fix), or repair costs more tokens than serial execution.

### 13. A risk-ordered review tour and comprehension-debt meter target the human bottleneck

**Mechanism.** At turn end, hunks are ordered by risk instead of by file. Risk is estimated from `internal/impact` reference counts and from whether a hunk changes behaviour, edits a test, or is mechanical. Mechanical churn (renames, formatting) is detected deterministically by AST equality modulo identifiers and collapsed behind a count. Each hunk shows the stated intent that `internal/change` already records. Separately, the TUI tracks lines approved without being expanded, per package, and surfaces "1,200 unread approved lines in pkg/auth".

**Why a step change.** Developers were **19% slower with AI while believing they were 20% faster** ([METR](https://metr.org/blog/2025-07-10-early-2025-ai-experienced-os-dev-study/)). AI help cut quiz mastery from about 67% to about 50%, with debugging hit hardest ([InfoQ](https://infoq.com/news/2026/02/ai-coding-skill-formation/)). Hunk-level risk explanation outperforms line or file granularity ([arXiv 2607.02782](https://arxiv.org/pdf/2607.02782)). Debugging is also the skill needed to catch special-cased tests.

**Builds on.** `internal/change`, `internal/impact`, `internal/diff`, `internal/tui`, `internal/webui`, and `internal/treesitter`.

**Novelty check.** Sourcegraph's Diff Tour is the nearest precedent, with no published evaluation ([Sourcegraph](https://7.6.sourcegraph.com/diff-tour.md)). No shipping agent has a comprehension-debt meter.

**Experiment and kill.** effbench can only test the prerequisite: on the r13 final diffs, measure what share of changed lines the AST check classifies as mechanical. **Kill if below 20%**, because there is then little to collapse. The real value needs a user study, which effbench cannot provide.

## Ideas considered and rejected, including five that repeat janetcode's own negatives

Several attractive ideas from the notes fail janetcode's own evidence, and listing them prevents a second round of the same experiments. **Masking-first compaction** is the best-evidenced external result (it halves cost at an equal solve rate, [arXiv 2508.21433](https://arxiv.org/pdf/2508.21433)), but `Agent.Prune` already tiers stubs, trims and archives before any summary, and **no benchmark run has ever compacted** (peak about 26k against an 80k threshold, [PRESSURE.md](../docs/benchmarks/compaction/PRESSURE.md)). It duplicates existing behaviour and has no headroom. **Speculative execution of read-only tools** (PASTE, SPORK) fails on the 98%/1% wall-time split. Only its round-trip-removing variant survives, as idea 2. A **content-addressed, Salsa-style tool-result cache** mostly duplicates the existing read dedupe and stale-read stubbing, and it speeds up the 1%. Its one live piece, early cutoff for verification, is a footnote to idea 2. **Cache-economics engineering** (append-only prefix, `prompt_cache_key`, hit telemetry) is already done: `internal/agent/prefix.go` exists, `prompt_cache_key` is wired into `internal/llm/openai`, and the hit rate is about 90%. Off-peak DeepSeek scheduling for benchmarks is a free 50% discount ([DeepSeek pricing](https://api-docs.deepseek.com/quick_start/pricing)), an operations note rather than engineering.

Five candidates repeat measured failures. **Mid-trajectory learned routing** (SWE-Router, vendor routers) runs into the one-class corpus (8/9, 11/12, 18/18) and the cascade result, where the live cascade got 7/9 against the cheap solo model's 8/9 at +22% cost per solve. It also pays a full re-prefill on every switch ([model-mix notes](../docs/notes/model-mix.md)). The **scout-to-fixer cross-model split** from SuperScout is kept only in its handoff-verification form (idea 5), because routing was worthless in that paper too. **An LLM trajectory monitor or critic** collides with the critic predictor that never beat the majority baseline and with mid-turn Jev's `stuck` recall of 0.07. LLM monitors also caught only 42–65% of SWE-scale cheating ([ImpossibleBench](https://arxiv.org/html/2510.20270v1)). **A Live-SWE-agent-style self-written tool library** relies on the model choosing to call new tools, the pattern that sank `run_plan`, advisor-as-tool and `then_run`. `internal/recipe` already crystallises working turns without a model. **Agent-written AGENTS.md or summarised cross-run experience** would face both the ETH finding that generated context files cut success 2–3% while adding over 20% cost ([Vaughan synthesis](https://codex.danielvaughan.com/2026/07/26/do-auto-generated-agents-md-files-actually-help-codex-cli-init-research-evidence-context-engineering/)) and janetcode's own negatives: sleep consolidation wrote 0 entries in 60 sessions, and ontology recall added nothing beyond exact paths.

A few more are deferred rather than rejected. An **embedded Datalog query engine over Go facts** and **e-graph patch deduplication** have no evidence for coding agents at all. A **trace-on-failure tool** (Delve/rr, or strace side-effect summaries for bash) has promising 2026 papers but no cost-benefit data, and rr does not run on macOS. A **Morph/Relace fast-apply model** adds a paid external dependency against vendor-only claims, while line-range edits already cut cost ×0.90 ([lineedit REPORT](../docs/benchmarks/lineedit/REPORT.md)). One live tension deserves its own experiment and not a ranked slot. Poisoned memory persists in **64.7%** of later sessions when it is injected into the system prompt, against **17.4%** when it is retrieved by tool ([arXiv 2606.04329](https://arxiv.org/pdf/2606.04329)). Yet janetcode measured its memory benefit as carried *by the always-in-prompt index line* ([memory REPORT](../docs/benchmarks/memory/REPORT.md)). The safe resolution is user-confirmed promotion of agent-written entries into the index. Whether that keeps the 0/4-versus-4/4 warm-session benefit is untested.

## Conclusion

The research turns janetcode's strategic question around. The open question is no longer which smarter model-in-the-loop layer to add. It is which facts janetcode already computes that the model never sees, or sees too late. Each near-certain win is a harness-side read of existing state: the baseline snapshot classifies probes and re-runs pre-image tests, the event log fact-checks handoffs, provenance labels taint, and the verify plumbing removes a round trip. The bold bets lean on assets no competitor combines: exact zero-token mid-trajectory branching, a deterministic verdict to ration sampling, and per-hunk provenance for causal minimisation. That combination is the moat. A vendor harness with a better model can copy any one feature, but not the ledger they all read from.

The binding constraint is measurement, not ideas. effbench's main set has two misses of headroom, gates almost never fail on capable models, and per-seed variance runs 2–3×. Two investments therefore come before any of the thirteen ideas: the **Impossible-effbench split**, which ideas 3, 4 and 8 all need and which measures the failure mode most relevant to cheap open models, and a routine **offline pre-screen on recorded sessions** (hit rates, trigger precision, qualifying-turn counts) that kills most bad ideas before a token is spent. janetcode has already shown that a harness-initiated mechanism with a tight trigger beats a clever tool the model ignores. The ranking above is that lesson applied systematically.
