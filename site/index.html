Terminal coding agent

janetcode

A terminal coding agent in a single Go binary. It reads and edits code, runs commands, and iterates on the result, with every mutating action shown to you as a diff before it happens.

What it is

janetcode is a command-line program you run inside a project directory. You give it a task in plain language; it reads files, searches the code, proposes edits, runs shell commands, and checks its own work, going back and forth with a language model until the task is done or it needs your input. It works with Anthropic's Messages API and with any OpenAI-compatible endpoint — OpenAI, xAI, Qwen, DeepSeek, OpenRouter, vLLM, Ollama and others — so it is not tied to one model provider.

Everything that changes a file or runs a command is shown to you first, as a diff or the command itself, before it happens (unless you have explicitly told it not to ask). Nothing is hidden after the fact: every change, every command and every model call is written to a local session log you can read, search and undo.

Why

Most of what makes an agent trustworthy is not the model — it is the harness around it: what it asks permission for, what it remembers, what it can undo, and whether it tells the truth about what a change actually demonstrated. janetcode's design leans on a few ideas:

  • Ask before acting. Editing a file, running a shell command, fetching a URL — each is a permission prompt with a diff or the exact command, until you decide it does not need to ask any more (see permission rules).
  • Verdicts, not claims. When the model says “done, tests pass”, janetcode checks: it watched which commands actually ran and what they returned, and reports a verdict based on that, not on the model's own words.
  • Nothing is silently lost. When the context window (the amount of conversation a model call can carry) fills up, the old part is summarised rather than deleted — a step called compaction — and the full text stays on disk so a fact the model needs later can still be looked up (see sessions and compaction).
  • Everything is local and readable. Sessions, memory and permission rules are plain files on your machine. There is no account and no telemetry endpoint.

On the numbers below: janetcode's own benchmark report found a 21% spread between three identical runs of one task set, and warns that a single-run comparison is not evidence. Anything cited here names what was measured and points at the report that measured it; treat any single figure as an estimate, not a guarantee.

A few measured results, each with what it measured and where the run lives in the repository:

  • Against Claude Code, on the same Claude models, all twelve test cells passed for both; on Haiku janetcode read 2.6M tokens against Claude Code's 4.2M and cost $0.54 against $1.49 (docs/benchmarks/harnesses/claude/).
  • Across eleven models and five harnesses, three runs each (3,300 task runs, 2026-09-10), janetcode passed 651/660 — the most of the five — at the lowest cost per solved task (docs/benchmarks/harnesses/eleven-models/).
  • Compaction (summarising the conversation when it grows large) lost no tasks in an eval that forced it on early: 11/11 passed either way.

See verification gates and verdicts for what “passed” means here, and the repository's docs/benchmarks/ directory for every run behind these numbers.

Install

Requires Go 1.25 or newer. Linux and macOS are where janetcode is developed and tested; Windows support is best effort (the cheapest path there today is WSL).

git clone https://github.com/xmonader/janetcode
cd janetcode
make install        # puts janetcode on your $GOPATH/bin

There is no pre-built binary download: installing means cloning the source and building it with the Go toolchain you already have.

60-second quick start

Set a key for a provider, then run janetcode inside a project. With Anthropic:

export ANTHROPIC_API_KEY=sk-ant-...
cd your/project
janetcode

Or point it at any OpenAI-compatible endpoint. Alibaba's Qwen coding plan and OpenRouter are both tested live:

# Alibaba Model Studio (Qwen coding plan)
export OPENAI_API_KEY=sk-...
export OPENAI_BASE_URL=https://coding-intl.dashscope.aliyuncs.com/v1
janetcode --model qwen3.7-plus

# OpenRouter
export OPENAI_API_KEY=sk-or-...
export OPENAI_BASE_URL=https://openrouter.ai/api/v1
janetcode --model deepseek/deepseek-v4-flash

# Ollama (local, no key needed)
export OPENAI_BASE_URL=http://localhost:11434/v1
janetcode --model qwen3-coder

Or skip the environment variables entirely and run /connect inside the program: pick a preset provider, paste a key, choose a model, and the choice is saved to the config file.

A prompt given as an argument starts the session with it, and -p runs one prompt non-interactively (“headless”) and exits — the shape you would use from a script or CI:

janetcode "explain how requests flow through this service"

# one-shot, scriptable: assistant text on stdout, tool activity on stderr
janetcode -p "add a --verbose flag to cmd/server" --yolo

--yolo means “run mutating tools without asking” — use it once you trust the task and the sandbox you are running it in. Without it, a headless run with no terminal to ask simply denies anything that would change a file or run a command.

Run janetcode --web to get the same session in a browser on 127.0.0.1:8787 instead of the terminal, or janetcode --doctor to check your configuration, provider keys, git, local tools and language servers in one pass.

Features, in brief

Every card links to a worked example — what you type, what janetcode prints back — on the features page.

Permission prompt & modes shift+tab Ask, plan, auto or yolo — save a rule once and stop being asked the same question. Sessions: resume & fork --resume Every conversation is saved, resumable and forkable; long ones are summarised rather than truncated. Undo & provenance /undo Revert a whole turn or one change, and see which turn wrote which line of a file. Verdicts, not claims /verify set The project defines what “done” means; janetcode reports what actually ran, not what the model claimed. Recipes & evals /recipe run Replay a turn's tool calls for free, or turn a real session into a regression test. Subagents /review A second, bounded conversation does one side task in its own context, optionally on a cheaper model. MCP, hooks & skills /mcp trust Plug in extra tools, house procedures and enforced checks, all through plain project files. Cost control /budget See tokens and spend as you go, and set a hard ceiling for a session or a headless run.
